# iwdg_project — IWDG 独立看门狗

**学什么**：给程序挂一条「看门狗」——主循环要是卡死了（死等外设、程序跑飞、
死循环出不去），没人喂狗，芯片就被强制复位，系统自己救自己。

## 硬件接线

| 引脚 | 功能 | 说明 |
|------|------|------|
| —    | 无需接线 | IWDG 是芯片内部外设，跑在 LSI 上，不占任何引脚 |
| PC13 | 板载 LED | 低电平点亮，用来看「程序活着没」 |

## 运行现象

烧录后：LED 先快速闪 3 下（开机指纹），之后一直以约 5Hz 闪烁——
狗每 100ms 喂一次，饿不死，程序持续运行。

## 实验：故意饿死看门狗

把 `main.c` 主循环里的 `HAL_IWDG_Refresh(&hiwdg);` 注释掉再烧录：

- 现象变成「3 连闪 → 短暂闪烁 → 又 3 连闪」无限循环；
- 因为没有喂狗，约 1 秒后 IWDG 超时把芯片复位了，复位后又从头开始跑。

## 关键知识点

- **超时时间怎么算**：`超时 ≈ (Reload + 1) × 预分频 ÷ 40000`。
  本工程预分频 32、重装 1250 → 约 1 秒。想改 2 秒就把 Reload 改 2500。
- **为什么叫「独立」**：时钟来自内部低速 RC（LSI ≈ 40kHz），跟主时钟无关；
  主时钟就算彻底跑挂，看门狗照样数数、照样复位。
- **LSI 不准**：手册范围 30~60kHz，所以 IWDG 只能做「保底复位」，不能当定时器用。
- **一旦启动无法关闭**：IWDG 没有关闭位，启动后只能喂狗或等复位。
  所以初始化放在最后，并且调试断点停住时狗照样数数——
  CubeIDE 里调试可在 Run → Debug Configurations 里把 watchdog 设为 freeze。
- **喂狗位置有讲究**：喂在主循环里，意味着「整个循环走完一次才喂一次」。
  如果循环里某一步会阻塞超过超时时间，狗就会误咬——要么调大超时，要么拆分阻塞。
- 和 **WWDG（窗口看门狗）** 的区别：WWDG 有中断、要求在「窗口区间」内喂，
  喂早了也咬；IWDG 更简单也更独立，工程上做保底一般用 IWDG。
