# 按键排错与消抖整理（2026-08-11）

做 key 这个工程的时候，按键折腾了我大半天，把排错过程和消抖的几种做法整理一下，顺便复习。

## 一、排错：两个坑

**1. LED 接在 PA12 上，灯一直亮，程序怎么写都没用**

一开始把 LED 接在 PA12 上，发现不管程序怎么改灯都亮着，先怀疑代码，改来改去没用。
查手册才知道 PA12 是 USB 的 D+ 引脚，Blue Pill 板子上有个 1.5k 电阻直接拉到 3.3V（USB 全速设备识别用的）。LED 要是接成 PA12 → LED → GND 这种，3.3V 会通过 1.5k 电阻、LED 一路到地，灯当然一直亮，跟程序一点关系没有。
结论：PA12 别拿来接 LED。实在要用，就接成 3.3V → LED → PA12 这种低电平点亮的接法，PA12 输出低时灯才亮。（图 1，见 docs/pa12_pullup.png）

**2. 按键怎么按都没反应**

按键中间是凹进去的金属弹片，一开始没按到位，弹片接触不良，信号压根没进来。另外还怀疑过是不是插反了，最后用万用表量通断才确认。这种问题先量硬件，别急着改代码。

## 二、为什么要消抖

机械按键按下去的时候，弹片会抖动，20ms 内会多次通断，直接读引脚会读到一堆毛刺。常规做法是延时之后再确认一次：第一次读到按下，延时 20ms，再读一次还是按下，才算真的按下。

```c
if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_3) == GPIO_PIN_SET)   // 第一次读到按下
{
    HAL_Delay(20);                                          // 等毛刺过去
    if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_3) == GPIO_PIN_SET) // 再确认一次
    {
        // 确认真的按下了
    }
}
```

这个写法直观，缺点也明显：HAL_Delay 会阻塞 20ms，而且只确认一次，后面想扩展单击、双击、长按就麻烦。

## 三、状态机消抖（推荐）

思路是固定周期扫描，比如每 1ms 扫一次，用一个计数器累加，连续 N 次（比如 5 次）读到同一个电平才确认状态变化。这样不阻塞，一次按下只产生一次事件，后面扩展单击/双击/长按都方便。

四个状态：空闲 IDLE → 按下消抖 DEBOUNCE_PRESS → 已按下 PRESSED → 松开消抖 DEBOUNCE_RELEASE。

```c
typedef enum {
    KEY_IDLE, KEY_DEBOUNCE_PRESS, KEY_PRESSED, KEY_DEBOUNCE_RELEASE
} KeyState;
static KeyState key_state = KEY_IDLE;
static uint8_t  debounce_cnt = 0;
#define KEY_DEBOUNCE_MAX   5
#define KEY_PRESSED_LEVEL  GPIO_PIN_SET

uint8_t Key_Scan(void)
{
    uint8_t level = HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_3);
    switch (key_state)
    {
    case KEY_IDLE:
        if (level == KEY_PRESSED_LEVEL) { debounce_cnt = 1; key_state = KEY_DEBOUNCE_PRESS; }
        break;
    case KEY_DEBOUNCE_PRESS:
        if (level == KEY_PRESSED_LEVEL) {
            if (++debounce_cnt >= KEY_DEBOUNCE_MAX) { key_state = KEY_PRESSED; return 1u; }
        } else { key_state = KEY_IDLE; }
        break;
    case KEY_PRESSED:
        if (level != KEY_PRESSED_LEVEL) { debounce_cnt = 1; key_state = KEY_DEBOUNCE_RELEASE; }
        break;
    case KEY_DEBOUNCE_RELEASE:
        if (level != KEY_PRESSED_LEVEL) {
            if (++debounce_cnt >= KEY_DEBOUNCE_MAX) { key_state = KEY_IDLE; }
        } else { key_state = KEY_PRESSED; }
        break;
    default:
        key_state = KEY_IDLE;
        break;
    }
    return 0u;
}
```

调用方式：在 SysTick 1ms 中断（或定时器）里每 1ms 调一次 Key_Scan()，返回 1 就是一次有效的"按下-松开"。

几个注意点：

- Key_Scan() 每次调用只执行一个状态分支，所以必须固定周期调用，不然计数不准
- 用 switch-case 写状态清晰，后面加长按、双击就是在状态里加分支
- "松开消抖"这段最容易漏。只做按下消抖的话，松开瞬间的抖动会被当成新的一次按下

状态机示意图见 docs/state_machine.png。

## 四、RC 硬件消抖

嫌软件麻烦可以上硬件：10k 电阻 + 100nF~1µF 电容做个低通滤波，时间常数 τ = RC = 1ms~10ms，毛刺被电容吃掉。（图 3，见 docs/rc_debounce.png）
优点：电路简单，程序不用管。缺点：要加硬件，而且 RC 充放电有延迟，按键按下去会有点"闷"，电容选太大按键响应就迟钝了。

## 五、几种方案对比

| 方案 | 阻塞？ | 可靠性 | 扩展性 | 成本 |
|------|--------|--------|--------|------|
| 软件延时 20ms | 阻塞 | 一般 | 差，只确认一次 | 无 |
| 状态机 | 不阻塞 | 好，N 次确认 | 好，可加单击/双击/长按 | 无 |
| RC 硬件滤波 | 不阻塞 | 好 | — | 要加硬件 |

实际工程 key/ 里用的是延时 + 再确认的写法，PA8 上拉输入、PA3 下拉输入两个按键，控制 PA12、PA7 两路 LED，完整代码见 key/Core/Src/main.c。

## 六、顺便记的几个知识点

- 三元运算符 ?:：`条件 ? 值A : 值B`，就是 if/else 的简写。比如 HAL_GPIO_WritePin(GPIOA, GPIO_PIN_7, led_on ? GPIO_PIN_SET : GPIO_PIN_RESET)
- GPIO_PIN_SET / GPIO_PIN_RESET 在 HAL 里就是 1 / 0：`#define GPIO_PIN_RESET 0u`、`#define GPIO_PIN_SET 1u`，所以也可以直接写 HAL_GPIO_WritePin(GPIOA, GPIO_PIN_7, led_on)
- 按键模块一般是 5 个脚、中间凹进去的弹片，插反了或没按到位都会没反应，先量通断再怀疑代码
