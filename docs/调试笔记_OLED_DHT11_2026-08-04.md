# OLED 显示 DHT11 温湿度：踩坑记录（2026-08-04）

蓝 pill（STM32F103C8T6）接 0.96 寸 SSD1306 OLED，把 DHT11 的温湿度显示到屏上。折腾了一整天，中间连不上调试器、字符乱码各种问题，最后总算调通了。记一份流水账，免得以后重新踩一遍。

先写结论：每 2 秒读一次 DHT11，屏幕显示 TEMP 和 HUMI，编译烧录都正常，代码提交在 commit 527cc39。屏幕效果大概是这样：

```
TEMP:25 C
HUMI:47 %
```

## 接线

OLED 是 0.96 寸白屏，SSD1306，128×64。

| 设备 | 信号 | 接哪 | 备注 |
|------|------|------|------|
| OLED | VCC | 5V | 一开始接 3.3V 死活不亮，换 5V 就亮了 |
| OLED | GND | GND | 记得共地 |
| OLED | SCL | PB6 | I2C1_SCL |
| OLED | SDA | PB7 | 别接成 B5，我一开始就接错了 |
| DHT11 | DATA | PA0 | 开漏 + 上拉 |
| DHT11 | VCC | 3.3V | |
| DHT11 | GND | GND | |

I2C 地址是 0x3C。OLED 模块背面自带 4.7k 上拉电阻，核心板 PB6/PB7 没有上拉是正常的，不用怀疑板子。

## CubeMX 里改的几个地方

- RCC 用 HSE 8MHz 外部晶振，时钟树 HSE → PLL×9 = 72MHz
- SYS → Debug 选 Serial Wire，这个最关键，不然后面烧完程序 ST-Link 就废了
- APB1 分频 /2 = 36MHz。F103 的 APB1 上限就是 36MHz，一开始设的 /1 属于超频
- PA0 配 Open Drain + Pull-up，适配 DHT11 单总线
- I2C1 用 PB6/PB7，Standard Mode 100kHz。杜邦线连的，速度放低点稳

## 踩的坑，按时间顺序记

**1. 烧完程序 ST-Link 连不上了**

现象：No device found on target。原因：CubeMX 里 SYS→Debug 默认是 No Debug，生成的代码把 SWJ 整个关掉了，PA13/PA14 不再当调试口用。
改法：把 stm32f1xx_hal_msp.c 里的 __HAL_AFIO_REMAP_SWJ_DISABLE() 换成 __HAL_AFIO_REMAP_SWJ_NOJTAG()，保留 SWD。
万一已经救不回来：BOOT0 拨到 1 进系统 bootloader，用 STM32CubeProgrammer 全片擦除。

**2. PA0 用推挽输出，和 DHT11 互相拉**

DHT11 是单总线，靠 MCU 拉低表示发 0、松手让上拉电阻把电平拉回 1 来通信，推挽输出干不了这活。改成 Open Drain + Pull-up 就好了。

**3. 时钟停在 8MHz**

没配 PLL，系统时钟一直用的 HSI 8MHz。加上 HSE + PLL×9 = 72MHz 才正常。

**4. APB1 超频**

APB1 Prescaler 设了 /1，PCLK1 跑到 72MHz，超过 F103 的 36MHz 上限，改成 /2。

**5. 新加的 .c 文件报 undefined reference**

CubeIDE 的 make 构建不会自动编译新加进来的源文件，得手动把 ssd1306.c 和 dht11.c 加进 Debug/Core/Src/subdir.mk（C_SRCS、OBJS、C_DEPS 三处）和 Debug/objects.list。
注意 Debug/ 被 .gitignore 忽略了，这个改动不会进版本库。以后换机器重新 clone，还得再手动加一遍，或者干脆让 CubeMX 自己管源文件。

**6. 只能按 RESET 才能连上调试器**

ST-Link 的排线没有 NRST 脚，软件里选 Connect under reset 发复位命令没人收。只能手动按板子上的 RESET 配合调试，或者 BOOT0 拨 1 救砖。

**7. SDA 接错，接到了 B5**

现象：I2C 总线上探测不到设备。改回 PB7 之后 LED 闪了两下，确认 0x3C 地址有应答。

**8. 显示发虚**

对比度 0xCF 太亮了，降到 0x7F 就正常。

**9. 显示拉长、颠倒、只占半屏**

128×64 的屏 COM pins 配错了，用了 0x02（那是 128×32 屏的值），改成 0x12 就好了。

**10. 字符错乱，TEMP 变成 IFUN —— 这个坑最久**

现象：TEMP 显示成 IFUN，HUMI 显示成 HNUT，方向、比例都没问题，就是字不对。一开始怀疑是 I2C 速度，降速一点用没有。
后来才发现是字库位序的锅：Font5x7 的字模数据里 bit0 对应这一列最顶行（标准 5×7 字模本来就是这么写的），但 SSD1306_WriteChar 里用 `glyph[col] & (1 << (7 - row))` 把 bit7 当顶行读，等于每个字上下颠倒，看起来就成了另一堆怪字符。
改法：把 `(1 << (7 - row))` 改成 `(1 << row)`，顺手把注释也改对。
结论：字符变形先查字库位序，跟 I2C 速度没关系，降速白折腾。

## 代码大概结构

- main.c：USER CODE 2 里 DHT11_Init() + SSD1306_Init()；while(1) 里每 2 秒 DHT11_Read() 一次，往屏幕写 TEMP:/HUMI:，最后 SSD1306_UpdateScreen() 刷屏。
- dht11.c：单总线时序，起始信号 19ms，然后 80µs 应答，读 40 位数据，最后校验和。微秒延时用的 DWT 循环计数器（72MHz 下 1µs 就是 72 个周期），没用粗糙的 HAL_Delay。
- ssd1306.c：1024 字节显存（framebuffer）+ 标准 5×7 字库，SSD1306_Init 上电序列、SetCursor/WriteChar/WriteString/WriteInt，UpdateScreen 整屏刷一次。

## 验证

干净副本命令行 make all，0 error / 0 warning，生成 lianxi_1.elf。实测 OLED 显示温湿度正常，2 秒刷一次。
